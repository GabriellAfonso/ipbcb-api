# Research: Doctrine Documents in the Database

Decisions taken before implementation. Settled points from the decision conversation (session
`2041feef-c82e-463c-b6c8-917c81b7498b`) are repeated here only with their reason; the rest are
plan decisions.

## R-01 Model name and placement

**Decision**: one model `DoctrineStandard` in `features/doctrine/models.py`, table owned by the
doctrine app. `verbose_name` "doctrine document".

**Rationale**: only the doctrine feature uses it, so it stays out of `core` (constitution). The
name `DoctrineDocument` is already the Pydantic union in `dtos.py`, which every layer imports;
reusing it for the model would force aliases in the repository and break the "names with few grep
hits" rule. "Standards" is the established name for the Westminster set.

**Alternatives**: `DoctrineDocumentModel` (suffix noise); a model per question/chapter (rejected in
the conversation: splitting only pays off for editing single items, and doctrine is never edited).

## R-02 Content column

**Decision**: `content = JSONField()` holding the `questions` list (catechism) or the `chapters`
list (confession), dumped from the validated DTO with `mode="json", exclude_unset=True`.

**Rationale**: `exclude_unset` keeps the stored JSON identical to today's file: a paragraph without
a list has no `lists`/`text_after` keys, while `"reference": null` stays (it is set explicitly).
Reading back through the DTO then reproduces the same `exclude_unset` dump the view returns, so the
response is byte-for-byte the old one plus `edition`/`year`. Same column type as the Sunday school
lessons (`026`), which works on both PostgreSQL and the SQLite test database.

**Alternatives**: storing the whole document (slug, title… duplicated with the columns, two
sources of truth); `exclude_none` (would drop the explicit `null` references).

## R-03 `edition` and `year`

**Decision**: `edition = CharField(max_length=120, blank=True)`, `year =
PositiveSmallIntegerField(null=True, blank=True)`. The repository maps an empty `edition` to
`None`, so both serve as `null` until a later data migration fills them. Both DTOs and the summary
get `edition: str | None = None` and `year: int | None = None`; the repository always sets them,
so the `exclude_unset` dump includes them.

**Rationale**: Django convention for text columns (no two "empty" values); the API contract says
`null` for "unknown". Defaults on the DTOs keep the frozen files and the test fixtures valid
without the keys.

## R-04 Initial load

**Decision**: `features/doctrine/migrations/0002_load_westminster_standards.py` (data migration,
reason at the top) reads the three files frozen in `features/doctrine/migrations/data/` with the
existing `load_doctrine_documents()` (schema, contiguous numbering, non-blank text, slug = file
name and slug format, unique `position`), then `bulk_create`s one row per document with `edition`
"" and `year` null. The reverse deletes the rows whose slugs the files hold. The files are moved
with `git mv` from `features/doctrine/data/` and rewritten as compact JSON (~420 KB instead of
~830 KB). `0001_initial` is generated by `makemigrations`.

**Rationale**: decided in the conversation over a `.sql` dump — runs on the deploy's `migrate`,
validates, depends on no local id. A validation failure raises inside the migration's
transaction, so `migrate` stops, nothing is loaded and gunicorn never starts (same outcome the
startup check gave). Importing feature code into a migration couples it to future DTO changes;
accepted as in `026` R-08, because the committed-files test fails if the DTOs ever stop accepting
the frozen files.

`loading.py` stays as the reader of a directory of document files, used only by the migration and
the tests; `DOCTRINE_DATA_DIR` now points at `migrations/data/`.

**Alternatives**: SQL dump (rejected by the user after discussion); copying the DTOs into the
migration (≈150 lines duplicated, against the no-duplication rule).

## R-05 Startup validation removed

**Decision**: `DoctrineConfig.ready()` and `validate_doctrine_data()` are removed, with
`tests/unit/test_startup_validation.py`.

**Rationale**: spec FR-013. The rule it enforced (never serve a broken set) is now enforced by the
migration (R-04) and by the check that the stored rows validate when read.

## R-06 Reading from the table (list query and content)

**Decision**: no cache and no deferred `content`. `DoctrineRepositoryImpl.list_documents()` reads
the three rows ordered by `position` and validates each into the DTO; `get_document(slug)` reads
one row by exact slug. The service keeps computing `item_count` from the DTO, unchanged.

**Rationale**: measured on the real data: validating all three documents takes ~23 ms and decoding
their JSON ~5 ms; the list is fetched rarely (the app revalidates with `ETag`), so a cache would
add invalidation concerns (tests, a future correction migration) for no visible gain (SC-005).
Deferring `content` on the list would need a backend-specific JSON-length expression (PostgreSQL
`jsonb_array_length` vs SQLite `json_array_length`) or a redundant `item_count` column the spec
does not have. Two queries' worth of work at most per request; no queries in loops.

A row whose content fails validation raises `pydantic.ValidationError` (a 500): it can only come
from a bad data migration, which the migration's own validation prevents.

**Alternatives**: in-process cache keyed by `updated_at` (rejected above); `.defer("content")` with
a stored count (spec model has no such field).

## R-07 Read-only

**Decision**: the model is **not registered** in the Django admin; the API keeps `GET`-only views
(`405` otherwise). A test asserts `admin.site.is_registered(DoctrineStandard)` is false.

**Rationale**: spec FR-007; the user: "a doutrina não pode ser editada". An unregistered model is
the simplest admin with no add/change/delete; a read-only registration would add code for a view
nobody asked for.

## R-08 Tests

**Decision**:

- `tests/data/test_committed_documents.py` points at `migrations/data/` and gains the check that
  only Larger Catechism Q153 and Q163 have a null reference.
- `tests/integration/test_load_migration.py` (new): a fresh test database holds the three documents
  equal to the frozen files, with `edition`/`year` null; reverse removes exactly them; forward
  again restores them.
- `tests/integration/conftest.py`: `fixture_doctrine` replaces the table rows with the two tiny
  fixture documents (ORM inside the test helper), and `reload()` re-stores them after a test edits
  the files. The views are no longer overridden in DI; they read the table.
- `tests/integration/test_doctrine_repository.py` (new): round trip keeps omitted keys omitted and
  `null` references `null`; empty `edition` reads as `None`; ordering by `position`; exact-case slug.
- `tests/integration/test_doctrine_api.py`: bodies now include `edition`/`year` (`null`); a new
  test asserts the admin has no doctrine model.
- Unit tests of `loading.py`, DTOs and service stay (fixtures unchanged).
